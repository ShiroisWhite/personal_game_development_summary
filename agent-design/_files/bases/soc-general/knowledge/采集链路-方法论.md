# 采集链路 · 方法论手册（沙盒生存通用）

> 适用：任何"采集原料 → 加工 → 分发"的开发链设计。
> 纯方法论 + 浅案例。仅作设计原理参考，**不是任一游戏的标准**。

---

## 0. 一句话定位

采集是循环的**原料入口**，但它最容易用最重的操作代价搬原料。设计采集，**先定"操作粒度"**，再谈玩法。

---

## 1. 两条轨道对照（教学价值最有意思）

| | 轨道A · 手动采集 | 轨道B · 据点加工 |
|---|---|---|
| 玩法 | 资源点 → 逐棵采 → 背包 | 定时半自动 + 掠夺货箱 |
| 操作粒度 | O(N×k) 逐件 | O(1) 点货箱 |
| 决策 | 只留"去哪采"，"采哪棵"零决策 | 留"守据点 / 抢产区 / 产线分布" |
| 节奏 | 站桩干等，无短时成果 | 定时生产 + 货箱销毁逼你回 |

> 结论：**A 用最重操作搬原料，B 才是"对的"**——减操作 ✅ 造节奏 ✅ 留决策 ✅ 三样都在。

---

## 2. 采集三要素（原料入口要同时满足才成立）

- **减操作**：批量 / 自动，O(1)
- **留决策**：到哪采 / 采什么 / 花多少
- **造节奏**：定期有成果、有期待感

> A 两头失（零决策 + 站桩干等）；B 三样都在但缺"投入"，纯白出没深度。

---

## 3. 三个数据洞（策划要盯的黑盒）

这些若被锁进服务端黑盒，策划就没抓手：
- **采集类型枚举语义**全表不清（类型值代表啥没注明）
- **采空 / 刷新 / 枯竭**完全不暴露给客户端——想看"一棵树采几次 / 刷多快"没地方调
- **产物去向**无目标列（进背包 / 仓库 / 工作台不明）

> 教训：采集的"刷新 / 枯竭 / 产物去向"必须可配置、可见，别封进服务端黑盒。

---

## 4. 决策检查清单（上线前自检）

- [ ] 操作粒度 O(1) 还是 O(N×k)？技术边界有没有泄漏到操作层？
- [ ] 减操作 / 留决策 / 造节奏三要素占了几样？缺哪样？
- [ ] 采集物"刷新 / 枯竭 / 产出"可配可见，还是黑盒？
- [ ] 产物去向明确吗（进哪个环）？
- [ ] 有没有本可挂机减负却被禁、逼玩家回逐件手采的？

---

## 5. 附：一条可复用红线

**采集是原料入口，必须 O(1) 批量；刷新 / 枯竭 / 产物去向要可配置、可见；别用最重的操作代价搬原料。**

---

## 6. 附：可迁移的"设计陷阱"原型（浅案例）

- **"减负"设备被屏蔽逼玩家逐棵采**：本可 O(1) 的自动采集被禁，玩家回逐件手采——用最重代价搬原料。
- **纯白出无投入的据点**：定时点了货箱白得，缺资源管理深度，产物偏随机箱而非选择。
- **两轨道成色差一个量级**——同是"采集"，一个操作粒度泄漏，一个接近最优。**操作粒度定生死。**
