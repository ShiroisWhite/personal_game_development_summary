# 循环模式库

本文件是设计模式参考，不是必须全部实现的清单。按当前底座的游戏类型选取。

## 1. 核心循环地图

```
        ┌──────────── 生存压力 ────────────┐
        ↓                                  │
   采集资源 → 制作工具/武器 → 建造据点 → 防御/战斗
        ↑                                  │
        └──── 更高阶区域 / 更强敌人 ←──────┘
```

四条并行子循环：

| 子循环 | 投入 | 产出 | 回流 |
| --- | --- | --- | --- |
| 生存 | 食物、水、温度管理 | 存活时间 | 更远探索 |
| 生产 | 资源、时间、设施 | 工具、建材、消耗品 | 更高效采集/建造 |
| 战斗 | 装备、弹药、风险 | 掉落、区域控制 | 更稀有资源 |
| 社交 | 时间、信任、贡献 | 分工、交易、保护 | 更大规模目标 |

## 2. 生存压力曲线

好的压力曲线不是“一直掉血”，而是**压力类型随进度变化**：

| 阶段 | 主要压力 | 玩家应对 |
| --- | --- | --- |
| 前期 | 饥饿、寒冷、黑夜、基础敌人 | 找食物、点火、简易庇护 |
| 中期 | 资源距离、装备损耗、区域危险 | 建立据点、规划路线、升级装备 |
| 后期 | 大规模敌人、其他玩家、维护成本 | 防御工事、团队分工、赛季目标 |

检查点：

- 前期压力是否让玩家在 10 分钟内理解规则？
- 中期压力是否迫使玩家离开出生区？
- 后期压力是否从“活下去”转为“守住/扩张”？
- 压力消失后有没有新压力源接替？

## 3. 生产链

### 3.1 工序 vs 分类

制造设施应按**工序**划分，而不是按物品分类划分：

- 工序：采集 → 精炼 → 加工 → 组装 → 建造
- 反例：武器台、防具台、工具台、家具台（这是分类，不是工序）

分类式设施会导致：同一材料要在多个台子之间搬运、配方重复、玩家操作碎片化。

### 3.2 中间产物共享

中间产物（木板、金属锭、零件）应属于**共享资源**，不属于任何单一设施。
否则每新增一条生产线，就要复制一套中间产物，配置与背包都会爆炸。

### 3.3 自动化程度

| 程度 | 玩家操作 | 适合 |
| --- | --- | --- |
| 手动 | 每次点击 | 前期、稀有制作 |
| 半自动 | 设置配方，等待产出 | 中期主力 |
| 全自动 | 规划输入输出，离线运行 | 后期、减负端 |

自动化必须保留决策（做什么、投多少、放哪里），只减少操作。

## 4. 建造与据点

### 4.1 建造的三层价值

1. **功能**：存储、生产、防御
2. **安全**：位置、结构、通行控制
3. **表达**：外观、布局、身份

前两层不成立时，第三层没有意义。

### 4.2 结构规则

- 承重/支撑规则是否清晰？
- 拆除是否返还材料？
- 错误放置的惩罚是否可逆？
- 移动端操作是否可行（旋转、吸附、批量拆除）？

### 4.3 防御价值

如果 PvP 存在，基地必须提供**可感知的保护**：

- 结构耐久 vs 进攻成本
- 离线保护机制
- 被攻破后的恢复路径
- 防御不应变成“永远打不进去”，否则对抗消失

## 5. 战斗与资源成本

- 战斗消耗必须与产出匹配：打一场是否值得？
- 高端弹药/装备的成本是否把玩家劝退？
- 装备损耗是“维修”还是“报废”？两者体验完全不同。
- PvE 与 PvP 的资源产出是否分离？PvP 零和时，PvE 必须能补血。

检查公式（设计建议，不是现有配置）：

```
单场净收益 = 掉落价值 + 经验价值 + 区域收益 − 弹药 − 耐久 − 补给 − 时间机会成本
```

如果长期净收益 ≤ 0，玩家会回避战斗，战斗系统就退化为展示。

## 6. 社交、交易与掠夺

| 模式 | 关系 | 风险 | 需要配套 |
| --- | --- | --- | --- |
| 合作 PvE | 正和 | 低 | 分工、共享奖励 |
| 交易 | 正和 | 中 | 价格发现、防诈骗 |
| 掠夺 PvP | 零和/负和 | 高 | 安全期、保护、恢复 |
| GVG | 零和 | 很高 | 身份分工、赛季目标 |

掠夺设计检查：

- 攻方所得是否约等于守方所失？
- 守方保留比例是否随区域风险变化？
- 被掠夺后有没有恢复手段？
- 离线玩家是否被保护？
- 掠夺是否变成“把其他玩家当时钟”——活跃度下降就死寂？

## 7. 进度与时间边界

| 机制 | 作用 | 代价 |
| --- | --- | --- |
| 等级/科技 | 稳定的成长感 | 后期可能只剩数值 |
| 图鉴/收集 | 内容驱动 | 容易变成清单劳动 |
| 赛季/剧本 | 给进度设闸，重置竞争 | 玩家可能反感“白玩” |
| wipe | 彻底重置 | 只适合高强度生存服 |

赛季设计要点：

- 重置什么、保留什么必须清晰
- 保留物要有“跨期价值”，否则玩家没有归属
- 赛季目标要改变玩法，而不只是提高数值
- 赛季末要有结算与展示

## 8. 局内局外结算

如果采用有边界/混合形态，需要三个设计键：

### 键 1：局内资源池

```
风险/回报 = 带出系数 / 带入成本
```

建议带出 > 带入，但设上限，防止滚雪球。

### 键 2：单局结算回收

```
局外回收 = Σ(局内产出 × 带出系数) − 已耗补给（弹药/耐久/入场费）
```

净期望应 > 0，但设上限；否则会变成印钞或秃鹫经济。

### 键 3：两种单局 + 保底

- 资源回收局：正和养成
- 对抗夺取局：零和风控
- 主世界保留家园/采集/建造/社交，作为“家”的保底

## 9. 节奏

| 节奏 | 时间尺度 | 设计目标 |
| --- | --- | --- |
| 操作节奏 | 秒 | 采集/战斗手感 |
| 单次会话 | 20–90 分钟 | 有明确开始与收尾 |
| 日常循环 | 天 | 稳定回报与期待 |
| 周循环 | 周 | 目标与社交 |
| 赛季循环 | 月/季度 | 重置与新鲜感 |

检查：玩家下线时，是否有“明天想回来”的理由？这个理由不能只是“资源会满”。

## 10. 公开样本参照

以下只作结构参照，具体结论需按当前版本验证：

| 样本 | 可借鉴 | 注意 |
| --- | --- | --- |
| 星露谷 | 挂机端经营：洒水器减操作、保留种植决策 | 不要加策略端复杂度 |
| 我的世界 | 沙盒建造自由、红石可选自动化 | 自由度高，内容消耗快 |
| 方舟 | 生物作为资产与代际养成 | 数值与时间成本高 |
| 塔科夫 | 有边界局内局外、带入带出 | 纯撤离，不适合家园向 |
| Rust | 无边界、wipe、强对抗 | 冷服与新人劝退 |
| 七日世界 | 剧本制（时间）× 永恒岛（空间） | 缝合复杂，需要清晰规则 |
| 帕鲁 | 自动化策略端 + 收集 | 策略端复杂度高 |
| 永末地 | 策略端自动化 | 与挂机端爽点相反 |

## 11. 模式选择清单

设计新系统前，先回答：

1. 它服务哪条子循环？
2. 它是策略端还是挂机端？两端不能混。
3. 它的产出谁消费？
4. 它的操作成本是 O(1) 还是 O(N×k)？
5. 它加入后，旧系统会变成僵尸吗？
6. 冷服/低活跃时它还成立吗？
7. 它需要新的时间边界或身份分工吗？
