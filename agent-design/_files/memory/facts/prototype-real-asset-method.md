做界面原型时，**尽量用项目已有 UI 切图（PNG）拼界面**，不要用 CSS 画假的。这样给老板/团队看时 UI 框架和实际游戏一致，只有交互逻辑是模拟的。

**两条路径**
1. **已有同模块原型**：以现有最完整版本为基底，只替换视觉层为真实素材，**不动交互逻辑**。
2. **全新界面**：从零写 HTML/CSS/JS，但底板、按钮、图标、进度条全用真实 PNG，CSS 只做布局和文字。

**素材来源（不要猜）**
- 素材路径以 Lua View 代码为准：`grep "Common\.\w+Path"` 找出 `path = Common.XXXPath.."filename"`，再到 `Common.lua` 查根路径。
- PC 端与手机端素材目录不同，做 PC 原型要用带 `PC` 后缀的变量。
- prefab 是二进制格式，读不到精灵引用，但图标/进度条从 Lua 取可 100% 准；面板底板靠模块目录 + 命名推导。

**交付**
- 必须输出单文件 `_standalone.html`：所有素材 base64 内嵌，任何人打开都不会裂图。
- 容器固定 1280×720，内部等比缩放，主流屏幕不需滚屏。
- 没对应素材的元素用 CSS/emoji 兜底，不强求造。

**Why:** 从零写只实现 15/61 功能点（缺 75%）；基于完整基底换皮 100% 保留功能。从零重写既浪费 token 又丢交互。
