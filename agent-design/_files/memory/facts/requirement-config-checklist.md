做需求时最容易踩的坑：只盯 Excel，漏掉协议里的权限/状态流转，或新功能漏加可掠夺字段破坏生存射击闭环。

**核心心法**：Excel 管数值，协议管流程和权限，prefab 管场景参数；多人玩法默认服务端权威有延迟；新数值走属性组、新配方走五层、新产能必加可掠夺字段。

**检查清单**
1. **配置来源三路查**：Excel（数值）+ 协议类定义（流程/权限/状态，多人玩法必查）+ prefab（场景参数）。"能不能做/做没做/哪个状态"的开关常在协议枚举，不在 Excel。
2. **服务器权威约束**（多人玩法）：请求→确认有往返延迟，需本地预览；命中以服务端为准有延迟感；AOI 限制远处对象，客户端不知道全图，全局实时信息要单独同步通道。
3. **新数值先查属性组**：先看属性枚举有没有现成项，不要加散字段。
4. **新配方看五层**：制作单元 → 子类 → 配方生成 → 标签 → 绘制，五层都要理清。
5. **新产能设施必加可掠夺字段**：漏了就是"产能高 → 风险低"的正反馈闭环。
6. **优先复用基础设施**：建筑块、核心保护、战报等已被多层玩法复用，新玩法先考虑复用而不是另起炉灶。

**Why:** 这是从代码 / 配置表 / 协议实勘里总结出的协作约定；也是最容易漏的三类坑。
