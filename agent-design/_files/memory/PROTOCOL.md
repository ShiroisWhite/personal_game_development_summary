# 记忆协议

## 为什么需要它

Claude Code 会把 `MEMORY.md` 自动注入上下文；dsh 不会。因此本包用**显式协议**替代自动注入：

1. 每次会话开始读 `memory/MEMORY.md`
2. 只加载与当前任务相关的事实文件
3. 出现需要长期保留的信息时，按本协议写入

## 文件格式

```markdown
---
name: short-kebab-slug
description: 一句话，说明什么时候该召回到它
metadata:
  type: user | feedback | project | reference
  updated: 2026-10-19
---

（正文：一条事实）

**Why:** （如果 type 是 feedback 或 project）

**How to apply:** （如果 type 是 feedback 或 project）

相关：[[other-slug]]
```

## 四种类型

| 类型 | 存什么 | 不存什么 |
| --- | --- | --- |
| user | 角色、能力边界、长期偏好 | 临时情绪、一次性需求 |
| feedback | 用户对工作方式的纠正/确认 | 模型自己的总结 |
| project | 已确认的项目设定、目标、约束 | 未确认的推断 |
| reference | 文档、URL、数据源指针 | 文件内容本身 |

## 写入规则

1. 一条记忆只讲一件事。
2. 先查重，再决定更新还是新建。
3. 只写用户确认过的、可验证的、会反复使用的信息。
4. 推断必须标注为推断；假设必须标注为假设。
5. 不写密钥、token、账号、个人敏感信息。
6. 涉密内容标注 `confidential: true`，并且只在本地使用。

## 召回规则

1. 先读索引，按 description 匹配。
2. 只加载相关文件，不要全量读取。
3. 记忆是时间点观察：引用文件、函数、配置前先验证仍然存在。
4. 记忆与当前事实冲突：以当前验证为准，并更新记忆。

## 维护规则

- 错误记忆：修正正文，记录修正原因。
- 作废记忆：删除文件、清理索引、告知用户。
- 重复记忆：合并到信息更全的一条，另一条删除并注明来源。
- 索引与文件不一致：以文件为准，重建索引行。

## 与内容底座的区别

| | 记忆 | 内容底座 |
| --- | --- | --- |
| 内容 | 关于用户与协作方式的长期事实 | 关于某个游戏/品类的领域事实 |
| 生命周期 | 跨会话、跨项目 | 跟随项目，可整体替换 |
| 位置 | `memory/` | `bases/<id>/` |
| 是否进入核心包 | 是 | 否 |

不要把项目数值写进记忆；它们属于内容底座。不要把用户偏好写进底座；它们属于记忆。
