# 记忆管理

## 存储

- 索引：`memory/MEMORY.md`
- 事实：`memory/facts/<slug>.md`，一条记忆一个文件
- 协议：`memory/PROTOCOL.md`

## 写入判定

只有满足以下任一条件才写：

| 类型 | 条件 | 例子 |
| --- | --- | --- |
| user | 用户角色、能力边界、长期偏好 | “我是策划，不做代码调试” |
| feedback | 用户对工作方式的纠正或确认 | “评审先看三轴” |
| project | 已确认的项目设定、目标、约束 | “这个底座只用于 X 项目” |
| reference | 外部资源指针 | 文档路径、URL、数据源 |

不写：临时任务状态、一次性路径、能从文件直接查到的东西、模型推断、未经确认的猜测。

## 写入流程

1. **查重**：读 `memory/MEMORY.md`，搜索同主题。
2. **决策**：已有则更新，不新建重复文件；内容冲突则先问用户。
3. **写文件**：

```markdown
---
name: short-kebab-slug
description: 一句话，用于召回
metadata:
  type: feedback
---

（事实正文）

**Why:** （为什么重要）

**How to apply:** （下次怎么用）

相关：[[other-slug]]
```

4. **更新索引**：在 `MEMORY.md` 对应分组加一行。

```markdown
- [标题](facts/slug.md) — 一句话钩子
```

5. **报告**：告诉用户写了什么、为什么、下次何时会用到。

## 召回流程

1. 读 `memory/MEMORY.md`。
2. 按 description 匹配当前任务，只加载相关文件。
3. 记忆是时间点观察：涉及文件、函数、配置时，先验证仍然存在。
4. 记忆与当前事实冲突时，以当前验证结果为准，并更新记忆。

## 更新与删除

- 旧记忆错误：直接修正正文，保留修正原因。
- 完全作废：删除文件，清理索引，并告知用户。
- 两条记忆合并：保留信息更全的一条，另一条删除并在正文中说明来源。
- 不要删除用户明确要求保留的记忆。

## 质量门槛

- 一条记忆只讲一件事。
- description 写“召回场景”，不是标题重复。
- 不把推断写成已确认事实。
- 不把密钥、token、账号写进记忆。
- 涉及前公司/涉密内容时，标注来源与保密级别，不写入对外材料。
