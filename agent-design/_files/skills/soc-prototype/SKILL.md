# HTML 高保真原型

## 适用场景

- 系统界面、交互流程、状态变化需要让策划/程序/美术快速达成一致
- 文字描述容易产生歧义，线框图又不足以表达体验
- 需要在评审前验证布局、信息层级、操作路径

不适用：需要真实数据与后端联调的验证；这时做可运行的最小功能，而不是原型。

## 流程

### 第 1 步：定义状态清单

先列状态，再画界面：

```markdown
| 状态 | 触发 | 界面表现 | 可用操作 |
| --- | --- | --- | --- |
| 空态 | 无数据 | 引导文案 + 主按钮 | 创建 |
| 默认 | 有数据 | 列表 + 筛选 | 查看/编辑 |
| 加载 | 请求中 | 骨架屏 | 取消 |
| 错误 | 失败 | 错误提示 + 重试 | 重试 |
| 完成 | 成功 | 结果 + 下一步 | 继续/返回 |
```

状态没列全，原型一定返工。

### 第 2 步：确定信息层级

- 一屏只解决一个主要任务
- 主操作唯一，次操作弱化
- 关键数值/状态放在视觉动线上
- 移动端与 PC 端的差异单独说明

### 第 3 步：写单文件 HTML

约束：

- 一个 HTML 文件，内联 CSS 与 JS，不依赖构建工具
- 中文字体使用系统字体或 Google Fonts（离线时回退）
- 用 CSS 变量管理颜色、间距、圆角
- 交互用原生 JS，状态用简单对象管理
- 不引入不必要的框架

结构建议：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>原型名称</title>
  <style>/* 变量 + 布局 + 组件 */</style>
</head>
<body>
  <main id="app"></main>
  <script>/* 状态 + 渲染 + 事件 */</script>
</body>
</html>
```

### 第 4 步：渲染检查

用 Chrome/Edge headless 截图或导出 PDF：

```bash
python tools/pdf_export.py 原型.html 原型.pdf
```

工具会：

- 自动查找 Chrome/Edge
- 处理中文路径（复制为临时 ASCII 文件名）
- 输出页数与文本量
- 失败时给出明确原因

截图检查项：

- 1280 / 1024 / 390 三个宽度
- 长文本换行
- 空态、错误态、加载态
- 按钮与点击区域
- 中文标点与括号

### 第 5 步：交接说明

原型交付时附：

```markdown
## 状态与交互
（状态清单）

## 与现有系统的差异
（新增/修改的界面与规则）

## 待确认
（需要策划/程序/美术拍板的点）

## 文件
（HTML 路径、截图路径、PDF 路径）
```

## 质量门槛

- 不交付“只有默认态”的原型。
- 不用假数据掩盖边界情况；边界数据要专门展示。
- 不引入需要联网才能看的依赖。
- 原型是沟通工具，不是最终实现；明确标注哪些是占位。
- 涉密项目的原型截图不外发。
