# SOC 设计评审清单

逐条勾选。不能回答的项标“未知”，不要默认通过。

## A. 目标与定位

- [ ] 一句话说清核心体验
- [ ] 目标玩家是谁，想要动脑还是省心
- [ ] 系统服务哪条循环（生存/生产/战斗/社交）
- [ ] 非目标写清楚了吗
- [ ] 成功时玩家会说出哪一句话

## B. 结构与循环

- [ ] 投入 → 转化 → 产出 → 回流 完整
- [ ] 产出有明确消费方
- [ ] 成长带来新决策，不只是新数值
- [ ] 风险随收益上升
- [ ] 失败有恢复路径
- [ ] 新系统加入后，旧系统不会变成僵尸

## C. 经济

- [ ] 产能与风险匹配
- [ ] 货币有产出、有回收
- [ ] 零和/负和有补偿或安全期
- [ ] 高端资源不被单一玩法垄断
- [ ] 通胀与稀缺有监控指标
- [ ] 战斗净收益长期 > 0

## D. 多人

- [ ] 合作是正和
- [ ] 掠夺有保护与恢复
- [ ] 离线玩家有保护
- [ ] 玩家有可选择的团队身份
- [ ] 冷服/低活跃时循环仍成立
- [ ] 后期对抗有实质奖励，不只是名次

## E. 时间与进度

- [ ] 进度有周期性封档或重置
- [ ] 重置什么、保留什么清晰
- [ ] 赛季目标改变玩法，不只是提高数值
- [ ] 内容消耗速度与产出速度匹配
- [ ] 新人有追赶窗口

## F. 操作与体验

- [ ] 操作成本是 O(1)，不是 O(N×k)
- [ ] 批量操作/自动化保留决策
- [ ] 关键状态有即时反馈
- [ ] 空态/错误态/加载态完整
- [ ] 移动端与 PC 端差异已处理
- [ ] 中文文案与标点规范

## G. 配置与实现

- [ ] 状态机定义完整
- [ ] 表结构主键/外键清晰
- [ ] 没有无消费方的字段
- [ ] 没有用配置表达代码逻辑
- [ ] 引用链无悬空
- [ ] 多语言 Key 完整
- [ ] 验收用例覆盖正常/边界/异常
- [ ] 回滚方案明确

## H. 文档

- [ ] 设计目的清楚
- [ ] 范围与非目标清楚
- [ ] 规则写成判定式
- [ ] 数值标注来源（现有/建议/待定）
- [ ] 风险与依赖列出
- [ ] 后续规划与未决问题列出

## I. 交付前最后三问

1. 如果只保留 20%，保留哪 20%？
2. 最可能失败的假设是什么，怎么最小成本验证？
3. 如果玩家用最优解绕过设计，会发生什么？

## 使用方式

- 评审前：把清单发给设计者自评。
- 评审中：逐条过，重点看“未知”和“不成立”的项。
- 评审后：把不通过的项转成行动项，指定负责人与时点。
- 不要把清单当打分表；它用于暴露风险，不是给设计打分。
