用户是游戏**系统策划**（game designer / planner），不是程序。

能做的：读、改 Excel 配置表；用编辑器看 prefab、查表结构、跑功能验收。
不能做的：打断点、看运行时日志、改 Lua / C# 代码。

**Why:** 这是反复确认过的协作边界。给他"去断点里看一下"等于让他做不了的事。

**How to apply:**
- 排查问题优先给**配置层可执行步骤**：字段值对不对、引用链完不完整、ID 是否匹配、开关走哪张表。
- 如果根因在代码逻辑：指出**具体文件名 + 行号 + 要改什么**，让他转交程序，而不是让他自己改。
- 输出验收方式时用"打开游戏点哪里、看到什么"描述，不用日志关键字。
