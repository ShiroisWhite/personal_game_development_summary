# 配置规划助手

根据策划案内容，输出一份完整的配置改动清单：**数据配置表 + 多语言表 + 代码改动点**。

## 项目路径速查（读 `skills/_project-paths.json`）

| 资源 | 字段 |
|------|------|
| Excel 数据配置表 | `config_root` |
| 多语言表 | `language_table` |
| C# 运行时代码 | `code_csharp` |
| Lua 逻辑 | `code_lua` |

字段为 `null` 时，跳过对应产物（例如没有 Lua 就不写 Lua 改动点），不要编造路径。换项目只改 `_project-paths.json`。

## 工作流程

### 第一步：输入理解

接收策划案（飞书文档链接 / 用户口述文本 / 贴入的文档内容），提取所有功能点。

对于每个功能点，判断它属于哪种**配置需求类型**：

| 功能类型 | 需要的配置表类型 | 示例 |
|----------|-----------------|------|
| 新实体/物品/单位 | `*Unit*` 表 + 语言表 `Item_*` | 新马种、新道具 |
| 数值参数/公式系数 | `*Param*` 表 或已有 Param 表加行 | 消耗速率、CD 时间 |
| 刷新/生成/刷新规则 | `*Refresh*` 表 | 刷新时间、刷新数量 |
| 客户端展示数据 | `*Data*` 表 | UI 显示的静态数据 |
| UI 面板文本 | 语言表 `System_*` / `UI_*` | 标题、按钮文字、说明 |
| 提示/报错信息 | 语言表 `Tips_*` | 成功提示、错误弹窗 |
| 任务/成就 | `Task*` 表 + 语言表 | 任务目标、奖励 |
| 消耗/产出/配方 | `*Cost*` / `*Exchange*` 表 | 材料消耗、兑换公式 |
| 建筑/设施 | `*Build*` 表 + `*Level*` 表 | 建筑属性、升级消耗 |
| 服务器参数（CD/上限等） | `RunParam` ID | 冷却时间、次数限制 |
| ⚠️ 纯程序/美术改动 | **无需配置** | 动画优化、特效调整、纯逻辑修改 |

### ⚠️ 不需要配置的情况

**以下类型的功能变动不需要配置表改动，必须在输出中明确指出：**

| 情况 | 说明 | 举例 |
|------|------|------|
| 纯客户端逻辑 | 只改代码行为，不涉及数据驱动 | 交互流程调整、按钮响应逻辑 |
| 纯美术/表现 | 只改资源，不涉及数据 | 特效替换、模型优化、动画调整 |
| 纯服务端逻辑 | 服务器内部计算，不暴露配置 | AI 行为树调整、匹配算法优化 |
| 已有配置的复用 | 用现有配置表的数据，不改结构 | 对已有道具数值的调整（只改值，不加字段） |
| 编辑器/工具改动 | 只改开发工具，不影响运行时数据 | Unity 编辑器扩展 |

**判断方法**：如果一个功能改动不需要"策划通过改表来调数值/文案"，那就不需要配置改动。**不确定时宁可标注 ❓需确认，也不能强行编造不需要的配置。**

### 第二步：参考已有系统

**必须执行**：搜一个功能最相似的已有系统作为参照。

- 用 Grep 搜关键词找到已有代码 → 看它读什么表 → 看表结构
- 新功能的配置结构通常可以复用同类系统的模式
- 输出时标注"参考 XX 系统"

### 第三步：输出配置规划

## 输出格式

```
## 📋 [策划案名称] 配置规划

### 一、新增 / 修改 Excel 数据配置表

#### 1.1 新建表
| 文件名 | Sheet | 用途 | 参考已有系统 |
|--------|-------|------|-------------|
| XXX.xlsx | XXXSheet | 描述 | 参考 YYY 表结构 |

#### 1.2 已有表新增字段/列
| 文件名 | Sheet | 新增字段 | 类型 | 用途 |
|--------|-------|---------|------|------|
| XXX.xlsx | XXXSheet | _NewField | int/string/float | 描述 |

#### 1.3 已有表新增数据行
| 文件名 | Sheet | ID | 关键字段值 | 用途 |
|--------|-------|-----|-----------|------|

### 二、新增多语言表条目

| Key 命名建议 | 文本内容 | 所属文件 |
|-------------|---------|---------|
| System_Guild_Share05 | "分享成功" | 8System_Text2.xlsx |
| Tips_ServerError_XXXX | "操作失败" | 11Tips_Text2.xlsm |

### 三、代码改动建议

| 文件 | 改动类型 | 说明 |
|------|---------|------|
| Assets/Lua/... | 新增读取 | GameTableManager.GetData<NewTable> |
| Assets/Lua/... | 新增 UI | 新面板 MVC |

### 四、无需配置的部分 ⚠️
> 以下功能点只需要程序/美术改动，不需要策划操作配置表：

| 功能点 | 原因 | 负责方 |
|--------|------|--------|
| XX动画优化 | 纯表现改动 | 美术 |
| YY逻辑调整 | 纯代码逻辑 | 程序 |

### 五、风险 & 注意事项
- 需要和程序确认的点
- 可能遗漏的边界情况
```

## 关键规则

1. **先搜后写**：输出建议前，必须搜代码和配置表确认类似功能的实现方式，不能凭空猜测
2. **标参考来源**：每个建议都标注"参考了哪个已有系统"或"参考了哪个已有表结构"
3. **不确定就标注**：对不确定的地方标记 `❓需确认`，不要假装确定
4. **区分新建 vs 修改**：新建文件和修改已有文件要分节列清楚，方便任务分配
5. **语言表 Key 要规范**：命名建议遵循现有命名规范（`System_[模块]_[描述]`、`Tips_ServerError_<ID>`）
6. **不强行加配置**：逐功能点判断是否真的需要配置改动。纯程序/美术/逻辑的需求直接归入"无需配置"并说明原因，不要为了显得"齐全"编造不需要的配置
