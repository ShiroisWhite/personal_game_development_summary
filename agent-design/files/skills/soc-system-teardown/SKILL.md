# SOC 系统拆解

## 输入

至少需要一项：系统名称、设计文档、配置表、截图、竞品描述或用户口述。
缺关键信息时，先问 1–3 个决定性问题（系统目标、服务哪条循环、玩家当前状态），其余标假设继续。

## 流程

### 第 1 步：定位系统在成长循环中的角色

成长循环：`采集 → 转化 → 变强 → 采集更高阶`。

判断它属于哪一层：

| 角色 | 判断标准 | 例子 |
| --- | --- | --- |
| 生存锚点 | 直接影响存活与安全 | 饥饿、温度、据点防御 |
| 生产转化 | 把原材料变成更高价值物 | 工作台、种植、养殖 |
| 进度结晶 | 把投入沉淀为长期资产 | 基地、科技、图鉴 |
| 身份表达 | 在前三层成立后提供差异 | 外观、专精、称号 |

一个系统可以有多重角色，但必须指出**主角色**。如果它不属于任何一层，先怀疑它是否真的需要存在。

### 第 2 步：定位三问

1. 它改变了玩家的哪种状态？（生存压力 / 成长节奏 / 自我表达 / 社交地位）
2. 它制造了什么决策？（资源投哪 / 基地放哪 / 先解锁什么 / 和谁合作）
3. 产出去了哪、谁在消费、成环了吗？

三问中任何一问答不上来，就是结构风险，不是数值风险。

### 第 3 步：画循环图

用文字或 Mermaid 画出：

```
投入（时间/资源/风险） → 转化（系统规则） → 产出（资源/能力/状态）
        ↑                                              ↓
        └──────────── 回流（产出成为下一轮投入） ←──────┘
```

必须回答：产出有没有回流？回流给谁？如果不回流，它就是“管子”，不是循环。

### 第 4 步：三轴判定

| 轴 | 正资产 | 负资产 | 判断 |
| --- | --- | --- | --- |
| 价值轴 | 循环，产出回流 | 管子，产出进仓库后消失 | 有没有回流 |
| 时间轴 | 持续产出价值 | 僵尸系统：被替代后仍占资源 | 新内容加入后它还活着吗 |
| 操作轴 | O(1) 批量操作 | O(N×k) 逐件操作 | 操作成本随规模怎么增长 |

操作轴要特别检查“实现粒度泄漏”：技术实现的最小单元（每棵树、每块田是独立对象）是否泄漏成了玩家操作的最小单元。

### 第 5 步：失败模式扫描

对照当前底座 `knowledge/` 中的失败模式清单，逐条判断“命中 / 不命中 / 不适用”。
至少覆盖：

- 管子非循环
- 僵尸系统
- 操作粒度泄漏
- 两种爽点混搭（策略端复杂度 + 挂机端离线生产）
- 产能与风险不匹配
- 货币/资源断链
- 后期只剩名次驱动

### 第 6 步：配置落点

如果当前底座包含配置表信息：

- 列出该系统涉及的表、Sheet、关键字段、引用关系
- 标出哪些是内容配置、哪些是数值、哪些是开关
- 指出缺失字段或过度参数化
- 不编造表名和字段；底座没有就写“当前底座未收录”

### 第 7 步：输出

按以下结构交付：

```markdown
## 结论
（这个系统成不成立，一句话）

## 定位
（角色 + 三问答案）

## 循环
（循环图 + 断点）

## 三轴判定
（价值 / 时间 / 操作）

## 命中的失败模式
（逐条：症状 → 根因 → 证据）

## 配置落点
（表 / 字段 / 引用 / 缺口）

## 风险与最小验证
（最可能失败的假设 + 一个最小可验证动作）
```

## 质量门槛

- 事实、推断、假设必须分开标注。
- 不得把结构问题说成“数值没调好”。
- 不得编造底座中不存在的表名、字段、数值。
- 至少给出一个可执行的最小验证，而不是只给结论。
- 用户是策划：涉及代码根因时，指出文件与行号，让他转交程序。
